# Finch 0.6 Implementation Plan

**Goal:** Make Finch easier to keep running and use daily: system-backed launch-at-login, verified notification/link behavior, and project-level daily usage.

**Architecture:** Use SMAppService.mainApp for modern login registration, retaining the existing owned LaunchAgent until successful registration. Extend the SQLite incremental index with usage ownership and 30-day retention. Keep collectors file-driven and render statistics from snapshots.

**Tech Stack:** Swift, AppKit, SwiftUI, ServiceManagement, UserNotifications, read-only Codex SQLite metadata, local SQLite usage cache.

## 1. Launch at login
- [x] Add LoginItemController.swift with actual system status, an approval state, failure messages and a system-settings button.
- [x] Recognize only the exact existing Finch agent; migrate without ending the running app or touching other startup jobs.
- [x] Add a settings switch, resync on app activation, and test legacy recognition/rejection with temporary plist fixtures.
- [x] Build and verify registration in the installed app; preserve the current enabled setting.

## 2. Notifications and links
- [x] Exercise existing lifecycle and notice policy coverage; verify authorization status without changing the user's settings.
- [x] Validate live Codex URI handling and use the native UI if accessible to verify an actual conversation click.
- [x] Add a direct system-notification-settings action and make delivery errors actionable.
- [x] Record visible verification separately from callback/URL-handler checks. Do not claim a banner or click was seen if UI access fails.

## 3. Project usage, history and browsing
- [x] Extend DailySource with resolved project and model metadata; keep daily scanning independent of the recent conversation list.
- [x] Write fixture assertions for precise/legacy counts, project attribution, copied logs, cache restarts, midnight, retained history and warm-cache bytes.
- [x] Add ownership and token components to indexed events, migrate v1 once, retain 30 days and show observed historical coverage.
- [x] Add a statistics view for today's project and model totals and 7/30-day local history.
- [x] Add session search, running/waiting filters, and configurable 24/50/100 conversation monitoring limits.

## 4. Compatibility, updates and delivery
- [x] Surface daily indexing failures and status scope; add a sanitized diagnostic copy action without paths, titles or credentials.
- [x] Add an explicit user-triggered GitHub release check; no automatic background network traffic or downloading/running executables.
- [x] Update both READMEs, architecture, changelog and version to 0.6.0. Add macOS build/test CI and checksum packaging.
- [x] Run meaningful suites and native fixture renders, install the checked build and leave Finch running.
- [x] Research whether official per-session quota is publicly supported; preserve absent/unknown values rather than estimating subscription charges.

## Validation
Use temporary roots and caches for automated testing and public screenshots. Run zsh test.sh and zsh build.sh to outputs/staging. Check codesign and plist syntax. Verify startup state against SMAppService and a live installed process. Measure a 30-second warm run, and keep cold backfill separate. Do not reboot, disable security protections, grant unrelated permissions or publish identifying fixture content.

## Outcome

Implementation and local verification are recorded in docs/validation-0.6.md. Notification banner visibility remains unverified: the user reported no banner and explicitly deprioritized this item. A normal native conversation click was confirmed by the user. Signing/notarization remains a future distribution task, not an implemented capability.
